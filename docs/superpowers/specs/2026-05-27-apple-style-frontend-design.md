# Apple 风格前端视觉改造设计

## 1. 目标

将当前 Vue/Vite 前端整理为更接近 Apple Photos 的视觉体验：简单、干净、美观、大方，同时保留适量细腻特效。

本次设计只覆盖前端视觉与交互质感，不改变现有业务能力、路由结构、后端接口或数据模型。

确认方向：

- 浅色模式采用 A 方案：极简 Apple Photos。
- 深色模式采用 C 方案：沉浸式暗色氛围，但控制特效强度，避免喧宾夺主。

## 2. 当前上下文

项目当前前端位于 `frontend/`，使用 Vue 3、Vite、Vue Router 和 `@lucide/vue`。现有页面包括图库、场景、人物、待整理、文件传输和设置。

已观察到的现状：

- 全局视觉已经有 Apple Photos / Liquid Glass 的雏形。
- `frontend/src/style.css` 承担了大量通用样式。
- `App.vue` 中已有鼠标位置变量和环境背景特效。
- 多个前端文件存在未提交修改，实施时需要保留现有改动，不覆盖用户工作。
- 当前部分中文文案出现乱码，需要在视觉整理时修复。

## 3. 设计原则

### 3.1 内容优先

照片、文件和工具内容是主角。背景、玻璃、阴影和动画只服务于层级关系，不作为主要视觉元素。

### 3.2 浅色模式克制

浅色模式采用 Apple Photos 式布局：

- 背景使用浅灰 `#f5f5f7` 附近的系统感页面底色。
- 侧边栏和工具栏使用轻微半透明材质。
- 卡片、照片网格和列表保持清晰边界，不使用强烈发光。
- 颜色以系统蓝作为主强调色，其他色彩只用于状态或媒体内容。

### 3.3 深色模式沉浸

深色模式采用 C 方案的氛围：

- 背景使用黑色和深灰。
- 可以保留少量蓝色、粉色环境光，强度低于 mockup。
- 面板、工具栏和弹层使用暗色玻璃质感。
- hover、页面切换和照片预览可以更明显，但不影响阅读。

### 3.4 特效可控

现有 `useEffects()` 和系统 `prefers-reduced-motion` 继续控制动效。

需要保留的特效：

- 页面切换淡入、轻微位移和 blur。
- 照片 hover 缩放。
- 卡片 hover 轻微抬升。
- 工具栏与侧边栏的毛玻璃。
- 深色模式少量环境光。

需要弱化或移除的特效：

- 浅色模式大面积装饰性光球。
- 过强的发光边框和阴影。
- 会分散注意力的持续动画。
- 与 Apple 风格不一致的高饱和渐变堆叠。

## 4. 视觉系统

### 4.1 颜色

浅色模式：

- 页面背景：系统浅灰。
- 主文本：接近 `#1d1d1f`。
- 次级文本：接近 `#6e6e73`。
- 面板背景：白色或轻微透明白。
- 主强调色：Apple 系统蓝。

深色模式：

- 页面背景：黑色或近黑。
- 主文本：接近 `#f5f5f7`。
- 次级文本：中性灰。
- 面板背景：深灰半透明。
- 环境光：少量蓝色和粉粉色，只在背景层出现。

### 4.2 排版

优先使用系统字体栈，贴近 Apple 平台观感。标题需要更干净、紧凑，避免过度夸张。

建议：

- 页面标题：约 32-36px，字重 700-800。
- 组件标题：约 16-20px，字重 600-700。
- 工具栏、侧边栏、标签：约 12-14px。
- 不使用负字距作为全局规则，只在少数大标题中谨慎使用。

### 4.3 圆角与阴影

整体圆角需要比当前更克制：

- 小按钮、侧边栏项目：8-10px。
- 普通卡片：12-16px。
- 大型预览、弹层：18-22px。
- 圆形头像和 pill 控件保留全圆角。

阴影用于层级，不用于装饰。浅色模式阴影更轻，深色模式用边框和背景层次替代重阴影。

## 5. 布局设计

### 5.1 应用框架

继续保留现有两栏结构：

- 左侧：应用侧边栏。
- 右侧：当前页面内容。

桌面端侧边栏保持固定宽度，内容区滚动。移动端可以继续隐藏侧边栏，但后续实现需要确保主要操作仍可访问。

### 5.2 侧边栏

浅色模式：

- 类似 macOS Photos 侧栏。
- 背景轻透明，边界细。
- 当前导航项用系统蓝或轻色高亮。
- 图标使用 lucide，尺寸统一。

深色模式：

- 深色玻璃面板。
- 当前导航项可以使用更明显的蓝色高亮。
- 品牌图标可保留轻微渐变，但不要过强发光。

必须修复侧边栏中文乱码，至少包括：

- 智能相册
- 图库
- 场景
- 人物
- 待整理
- 文件传输
- 设置
- 浅色模式 / 深色模式

### 5.3 顶部工具栏

工具栏继续 sticky。

浅色模式：

- 背景与页面底色融合，滚动时呈现轻微毛玻璃。
- 搜索框、按钮和视图切换使用轻边框。

深色模式：

- 使用暗色透明背景。
- 搜索框聚焦时允许轻微蓝色描边。

### 5.4 内容区

图库和场景页面应让照片缩略图承担主要视觉表达。统计卡、空状态、设置卡应更安静，不要做成大面积彩色卡片。

文件传输页面偏工具属性，应比图库更规整、紧凑，保持扫描效率。

## 6. 组件影响范围

主要涉及：

- `frontend/src/App.vue`
- `frontend/src/style.css`
- `frontend/src/components/AppSidebar.vue`
- `frontend/src/components/EmptyState.vue`
- `frontend/src/components/TopToolbar.vue`
- `frontend/src/components/PhotoMasonry.vue`
- `frontend/src/components/PhotoPreviewModal.vue`
- `frontend/src/views/SettingsView.vue`

实施时可以按实际样式引用情况缩小范围。不要为了视觉改造重写路由、composable 或后端 API。

## 7. 交互与动效

保留：

- 页面切换动画。
- 卡片进入动画。
- 图片 hover 缩放。
- 按钮 active 缩放。
- 深色模式背景缓慢环境光。

调整：

- 浅色模式默认不显示大面积环境光。
- 深色模式环境光透明度降低，且不覆盖内容层。
- 所有动画继续尊重 `prefers-reduced-motion`。
- 特效开关关闭时应移除持续动画和背景装饰。

## 8. 可访问性与响应式

要求：

- 文本与背景对比度保持可读。
- 焦点态清晰。
- 移动端不出现文字重叠、按钮挤压或内容横向溢出。
- 固定格式控件使用稳定尺寸，避免 hover 或状态变化导致布局跳动。
- 设置页面的开关、说明和状态文本在移动端保持可读。

## 9. 测试与验收

实施完成后需要验证：

- `npm run build` 通过。
- 浅色模式符合 A 方案：极简、干净、照片优先。
- 深色模式符合 C 方案：更沉浸，但不影响内容阅读。
- 侧边栏、设置页和空状态中文不再乱码。
- 主要页面在桌面和移动宽度下不重叠、不横向溢出。
- 特效开关和 `prefers-reduced-motion` 下没有持续动画干扰。

建议手动检查页面：

- 图库
- 场景
- 人物
- 待整理
- 文件传输
- 设置

## 10. 非目标

本次不做：

- 后端接口变化。
- 新增功能页。
- 图片数据模型调整。
- 文件上传逻辑调整。
- 大规模组件拆分。
- 引入新的 UI 框架。
- 引入新的动画库。
